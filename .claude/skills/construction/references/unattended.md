# 無人モード

`progress.md` の `## モード` が `unattended` のときの扱い。それ以外のときは各スキルの `## 承認ゲート` のとおりに進める。

**なぜ分けるか**: 無人実行では承認を返す人がいない。`AskUserQuestion` を呼ぶと応答が来ないまま止まり、外からは動いているのか固まっているのか見分けがつかない。

## ステージの途中で人に確認する手順に当たったら

ステージには、承認ゲートに着く前に人へ確認する手順がある（`explore` の「未解決の疑問をユーザーに確認して解消する」など）。無人時はここで止まると、ゲートの読み替えに届かないまま固まる。

当たったら次のどちらかにする。

- **既存のコード・`docs/rules/`・上流の成果物から決められる** — 確認せずに決めて進み、判断と根拠を memory に書く
- **外部に見える約束に関わる** — 下の「止まるとき」に従って中断する

## ステージ末の処理

承認ゲートの ①〜④ を次のように読み替える。

| | 有人 | 無人 |
| --- | --- | --- |
| ①成果物サマリー | ユーザーに提示する | `progress.md` に書く |
| ②センサー結果 | 提示する（参考） | 変わらない。結果は memory に残す |
| ③記録の振り分け | ユーザーに聞く | 下の「記録」のとおり自動で書く |
| ④承認 / 修正指示 | `AskUserQuestion` | 呼ばない。`[x]` にして次へ進む |

`[?]`（承認待ち）と `[R]`（修正中）は無人時には使わない。ステージ内の手直しは `[-]` のまま行う。

CONDITIONAL ステージのスキップも確認せず、判定と理由を memory に書いて決める。

## 記録

書式は `${CLAUDE_PROJECT_DIR}/docs/recording-conventions.md`。**無人時は迷ったら書く**。判定で捨てたものは成果物にもコミットにも現れず、あとから拾い直せないため。

- **memory** — 有人時と同じ
- **ADR / 用語集 / `docs/rules/`** — 判定を満たすものは書く
- **`records.md`**（`docs/intents/<slug>/units/<unit>/`）— 書いたものと、候補に挙げたが**書かなかったもの＋理由**を並べる

`records.md` が取捨選択の入口になる。人はレビューのときにこれを読んで、要らないものを消す。

## 止まるとき

判断を人に返すのは、**外部に見える約束に関わるとき**だけ。

1. 仕様・Unit の境界・受け入れ条件に関わる不明点が出た
2. Unit のスコープ外の変更が必要になった
3. 検証が通らず、`construction-verify` の失敗対応（**最大2回**）でも直らなかった

止めないもの: 命名・内部の作り・テストの書き方など、既存のコードと `docs/rules/` から決められること。

止めるときは `blocked.md`（`docs/intents/<slug>/units/<unit>/`）に、**何の判断が要るか・なぜ進めないか・どこまでやったか**を書き、progress を `[B]` にして終える。

ステージをまたぐ差し戻しが必要になったときも `[B]` にする。どこまで戻すかを決めるのは人の判断のため。
