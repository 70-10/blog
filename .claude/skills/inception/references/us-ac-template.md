# US / AC テンプレート

`02_user-stories.md` を書くときの形式。

## ユーザーストーリー（US）

各 US は次の形で書く。番号は `US-01` から振る。

```markdown
### US-01: <短いタイトル>

- **As a** <誰が>
- **I want to** <何をしたい>
- **So that** <なぜ／どんな価値>
- **優先度**: Must / Should / Could
- **参照**: <会話・Issue・既存記事・外部資料などのリンク>

#### 受け入れ条件（AC）

（下の Gherkin で書く）
```

「誰が・何をしたい・なぜか」を 1 文ずつに分けるのは、価値（So that）が曖昧な US を早く見つけるため。

個人ブログでは「誰が」の多くが「読む人」か「書く人（自分）」になる。どちらかが分かるだけでも後の判断（表示に関わるか、執筆の手間に関わるか）が変わるので省かない。

番号（`US-01`）は後工程が参照する。テスト設計の `completeness` センサーがこの番号を見て、触れられていない US を検出する。番号を振らないとこの検出が働かない。

## 受け入れ条件（AC）

AC は各 US の中に Gherkin（Given / When / Then）で書く。**別ファイルに切り出さず US に統合する**（US と AC が別管理だと更新時にずれるため、US を 1 か所にまとめる）。

```markdown
**シナリオ: 正常系 - <何をしたとき>**

- Given <前提の状態>
- When <操作>
- Then <期待する結果>

**シナリオ: 異常系 - <不正な入力をしたとき>**

- Given ...
- When ...
- Then ...
```

## AC の6観点チェックリスト

AC を書き終えたら、各 US について次の 6 観点が網羅されているか確認する。該当しない観点はスキップしてよいが、その判断理由をユーザーに確認する。仕様が未確定の観点は推測で埋めず `questions.md` に残して確認する。

| 観点 | 確認すること |
|---|---|
| 正常系 | 主要な操作・表示が期待どおりか |
| 異常系（データの不備） | frontmatter の欠落・不正な日付・空の本文・想定外のタグなど、コンテンツ側の不備をどう扱うか。ビルドを止めるのか、その項目だけ落とすのか |
| ビルドと生成物 | ビルドが通るか。生成物（OGP 画像・RSS・タグページ・静的ルート）に反映されるか |
| 既存コンテンツへの影響 | 既存の記事・一覧・タグページ・パーマリンクが壊れないか。URL が変わるなら移行をどうするか |
| 表示 | 画面幅による崩れ。ダークモードなど表示テーマがある場合はその切り替え。長いタイトル・多いタグなど極端なデータでの見え方 |
| 共有・SEO | タイトル・description・OGP・canonical が意図どおりか |

観点はこのリポジトリの作りに合わせてある。当てはまらない変更（ビルドに関わらない修正など）では該当分をスキップしてよい。
