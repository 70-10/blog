# inception

このリポジトリへの変更について Inception（要件整理）を行うスキルです。「何を作るか」をユーザーストーリー(US)・受け入れ条件(AC)まで落とし、実装できる単位（Unit）に割ります。

## 使いどき

新しい変更の要件を整理したいときに使います。次のように呼び出します。

- 「Inception をやりたい」
- 「何を作るか固めたい」
- 「US を書いて」
- 「AC を整理して」

途中から再開もできます。既存の `docs/intents/<slug>/` があれば、成果物の状態から自動で再開点を判定します。

## 流れ

5 ステップで進行します。各ステップの終わりに承認を取ってから次へ進みます。

0. **起点整理** — 何を・誰のために・どこまで作るかを固める
1. **現状・制約の把握** — 触る既存の実装・コンテンツ・外部サービスへの依存を洗い出す
2. **ユーザーストーリー** — 「誰が・何をしたくて・なぜか」の単位に分ける
3. **受け入れ条件(AC)** — 各 US に Gherkin（Given/When/Then）形式で AC を付ける
4. **Unit 分割** — 1 回の Construction で回せる大きさに割る（`unit-splitting` に委譲）

## 生成物

`docs/intents/<slug>/` 配下に以下が作られます。

| ファイル | 内容 |
|---|---|
| `00_intent.md` | 目的・スコープ |
| `01_current-and-constraints.md` | 既存の実装・依存・制約 |
| `02_user-stories.md` | US + AC |
| `03_units.md` | Unit 分割と依存・順序 |
| `questions.md` | 確認した Q&A の記録 |
| `memory/step0.md` 〜 `step4.md` | 各ステップ実行中の判断 |

加えて、用語は `docs/glossary.md`、設計判断は `docs/adr/`、確定した実践は `docs/rules/` に記録されます。どこに書くかは各ステップ末の承認ゲートで決めます。
