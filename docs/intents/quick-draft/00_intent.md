# quick-draft — 起点整理

## なぜ作るか（Why）

記事を 1 本書き始めるまでの準備が多すぎて、着想したことが記事にならないまま流れている。

思いついた瞬間に書き残せれば記事になったはずのものが、「あとで PC を開いたときに」と先送りされ、そのまま失われる。書く気そのものは十分にある。詰まっているのは PC という前提と、書き始めるまでの手数。

そして、下書きを残して整えられても、公開が PC 待ちになるならそこで止まる。着想から公開までひと続きで届いて初めて記事になる。

## 解決する課題

1. **PC を持ち歩いていないときに着想を書き残す手段がない。** 外出中に思いついても、記憶に頼るしかない
2. **PC があっても書き始めるまでの準備が長い。** ターミナルを開く → リポジトリへ移動 → `git pull` → `pnpm create-post` を通らないと本文に手をつけられない
3. **書き上げても公開が PC 待ちになる。** 整えるところまで手元で進んでも、最後の一歩で止まる
4. 結果として、**着想が記事として世に出ないまま失われる**

課題 1 と 2 は別の痛みだが、原因は同じ「書き始めるまでの手数」にある。1 は手数が無限（端末がない）に振れた極端な場合。課題 3 は 1 と同じく PC を前提にしていることから来る。

## スコープ（In / Out）

### In

- 端末を問わず、着想したときに下書きを残せるようにする（スマホだけの状況を含む）
- 残した下書きを、そのまま記事として書き継げる状態にする（下書きから書き直しにならない）
- **記事を書き始める間口を広げる。** 今の経路に加えて、より少ない手数で始められる入口を用意する
- **端末を問わず記事を公開できるようにする。** 公開のために必要になる既存の修正（校正の通し方、公開日の扱いなど）も含める
- **溜まった下書きを見返して整理できるようにする。** まとめるもの・捨てるものを判断できる

### Out

- **記事の正の置き場を変えること。** 記事はこのリポジトリ内の Markdown のまま。過去に Contentful を使っていたが管理のしづらさで手放した経緯があり、外部サービスを正にする案は採らない
- **既存の PC 経路（`pnpm create-post`）の廃止・作り直し。** 今の経路はそのまま残す。目的は入口を増やすことであって、既存の入口を置き換えることではない
- **下書きに画像を含めること。** 下書きはテキストだけでよい。画像は PC で書き継ぐときに入れる
- **下書きの段階での校正（textlint）。** 下書きは校正の対象外とする。校正が働くのは公開のときで、指摘があれば公開を止める（US-05 の受け入れ条件）

## 完了の定義

1. PC を開かずに、着想を下書きとして残せる
2. 残した下書きから、書き直しなしで記事の執筆を続けられる
3. 今の経路（ターミナル → リポジトリ移動 → `git pull` → `pnpm create-post`）より少ない手数で書き始められる入口がある。今の経路もそのまま使える
4. PC を開かずに、記事を公開できる
5. 溜まった下書きを見返して、まとめる・捨てるを判断できる

いずれも測れる形にはステップ 3 の受け入れ条件で落とす。

## 参照

- 現状の公開経路: `main` への push で Cloudflare Pages がデプロイ（リポジトリ内にデプロイ設定はなく Cloudflare 側で連携）
- 現状の執筆経路: `tools/create-post`（`pnpm create-post`）
- 記事の形: `src/content/posts/*.md` + frontmatter（`src/content.config.ts`）
- 校正: `lefthook.yml` の pre-commit で textlint
