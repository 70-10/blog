無人実行なので、承認ゲートで人に聞く代わりにここへ並べる（[ADR 0007](../../../../adr/0007-unattended-runs-move-recording-decisions-to-review.md)）。**要らないものを消すのがレビューの仕事。**

判定の基準は [記録の書式](../../../../recording-conventions.md)。

**判断の材料**

- Construction の 2 件をフェーズのファイルに置いたのは、どちらも Construction のステージ構成（explore → design の役割分担、`[B]` の扱い）に固有だから。既定は `project.md` だが、Inception には効かない
- `glossary-drift.sh` の件を `project.md` に置いたのは、Inception の 5 ゲートでも Construction の 7 ゲートでも同じ手順を踏むため
- 「管理画面」を登録したのは、[ADR 0006](../../../../adr/0006-build-our-own-admin-screen-for-writing.md) 以降この語が Unit をまたいで出てくるのに揺れやすいため。無人時は迷ったら書く方針に従った。**要らないと判断したら消してよい**
- **避ける別名を足すと、既にある文書の判定が後から変わる。** そこで `docs/` 全体に `glossary-drift.sh` を掛け直した。新しい 5 つの別名（管理ツール / 執筆画面 / エディタ画面 / admin 画面 / CMS）が当たったのは、この `records.md` の中で別名そのものを名指ししている行だけ。**既存の文書は 1 件も揺れていない**
- 併せて出た `メモ` / `エントリ` / `ネタ` の指摘（`docs/adr/0005`・`0006`、`docs/recording-conventions.md`、[execution-plan.md](../../execution-plan.md)、[questions.md](../../questions.md)）は**この Unit の変更より前からあるもの**で、いずれも引用か別の意味での用法。この Unit では触らない
- [03_units.md](../../03_units.md) の「編集画面」は管理画面の一部を指す語であって別名ではない。統一語に寄せない

### 中断が解けたあとに書いたもの

Stage 1 の途中で `[B]` にして人に返した判断が決まったので、書き足した。**ここは無人実行ではなく、人が選んだ結果。**

| 種別 | 置き場                                                                                                | 中身                                                                                                                          |
| ---- | ----------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| ADR  | [docs/adr/0008](../../../../adr/0008-admin-runs-as-its-own-pages-project-behind-cloudflare-access.md) | 管理画面は独立した Pages プロジェクトに置き、入口は Cloudflare Access で守る。却下した代替案 4 件つき                         |
| 疑問 | [questions.md](../../questions.md)                                                                    | 「管理画面をどこで動かし、認証をどう作るか」を未解決から解決済みへ移した                                                      |
| 制約 | [explore/constraints.md](explore/constraints.md)                                                      | 「管理画面の土台（Cloudflare / GitHub）」を追加。**すべて公開ドキュメントで裏を取ったもので、出典つき**                       |
| 削除 | `blocked.md`                                                                                          | 中断が解けたので消した。案の比較は ADR 0008 へ、確かめた事実は `constraints.md` へ移した。元の内容はコミット `ffc641e` にある |

ADR を書いたのは、[記録の書式](../../../../recording-conventions.md) の 3 条件をすべて満たすため。①後戻りしにくい（この構成の上に画面・裏側・テストの全部が乗る）②文脈なしでは驚く（なぜ別プロジェクトなのか、なぜ Access なのかはコードから読めない）③本物のトレードオフ（4 つの代替案から理由を持って選んだ）。

**この決定は人が用意するものを伴う。** 一覧は [explore/open-questions.md](explore/open-questions.md) の「人がリポジトリの外で用意するもの」にある。Stage 4（implement）に入る前に揃っている必要がある。

## Stage 2: design

### 書いたもの

| 種別   | 置き場                                                                                                              | 中身                                                                                                          |
| ------ | ------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| ADR    | [docs/adr/0009](../../../../adr/0009-drafts-live-outside-the-posts-collection-and-commit-with-a-build-skip-flag.md) | 下書きは posts コレクションの外に置き、`main` にビルドを飛ばす印を付けてコミットする。却下した代替案 3 件つき |
| ルール | [docs/rules/project.md](../../../../rules/project.md)                                                               | Git の節に追記。管理画面が自動で打つコミットは `[CI Skip]` を先頭に置き、型はその後ろに来る                   |

**ADR を書いた理由**（[記録の書式](../../../../recording-conventions.md) の 3 条件）: ①後戻りしにくい（置き場を変えると Unit 2 の公開の処理も書き直しになる）②文脈なしでは驚く（なぜ `src/content/posts/` に置かないのか、なぜコミットメッセージに `[CI Skip]` が付くのかはコードから読めない）③本物のトレードオフ（コレクションの中に置く案・専用ブランチ案・リポジトリの外に置く案から選んだ）。

**ルールを書いた理由**: `docs/rules/project.md` は「コミットメッセージは Conventional Commits」と書いたままなので、`[CI Skip] chore(draft): ...` を見た人が違反と読む。**定めのある場所で例外を書かないと、同じ事実が ADR とルールで食い違う。**

## 併せて報告すること（記録ではない）

Stage 1 で気づいたもの。[docs/recording-conventions.md](../../../../recording-conventions.md) の「ルールの置き場」に食い違いがある。「**既定は `project.md`**」と書いた直後に「狭いほうを既定にするのは…」と続くが、`project.md` は 3 つのうち一番広い。[docs/rules/project.md](../../../../rules/project.md) 自身も「昇格の既定はこのファイル」と書いているので、**既定は `project.md`** として振り分けた。どちらが意図かは書いた人にしか分からないので直していない。
