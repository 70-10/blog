**この Unit が受け持つのは US-01 と US-03 だけ。** US-02 / US-04 / US-05 は Unit 2 / 3 / 4 の担当（[03_units.md](../../../03_units.md)）。

## 動作検証結果

**実際に動かして確かめる観点（[test-cases.md](../test-design/test-cases.md) の T10）は 1 件も実施していない。**

理由は 1 つ。**デプロイと Cloudflare Access の設定が要り、それは AI にはできないため。**[人がリポジトリの外で用意するもの](../explore/open-questions.md) 4 つが揃うまで実施できない。

| #   | 確かめること                                          | 状態       | 何が要るか                                                |
| --- | ----------------------------------------------------- | ---------- | --------------------------------------------------------- |
| M1  | スマホから管理画面を開き、下書きを残して開き直せる    | **未実施** | Pages プロジェクト・サブドメイン・トークン                |
| M2  | 自分だけが入れる（別のアドレスでは入れない）          | **未実施** | Zero Trust と Access のポリシー                           |
| M3  | 本文に最初の一文字を打つまでの手数が 4 未満           | **未実施** | 上記すべて。**人が数える**                                |
| M4  | 下書きが実際に GitHub の `src/content/drafts/` に入る | **未実施** | トークン                                                  |
| M5  | 下書きの保存で Cloudflare Pages のデプロイが走らない  | **未実施** | 実際の push。`[CI Skip]` が効くかは push でしか分からない |

**コードを読んで満たしていそうだから合格、とはしていない。** 上の 5 つは「未実施」であって「満たさない」でも「満たす」でもない。

## 未カバーの条件分岐

### テストで触れていない分岐

| 分岐                                             | なぜ触れていないか                                                                  |
| ------------------------------------------------ | ----------------------------------------------------------------------------------- |
| `github.ts` の 404 / 409 / 422 以外の失敗        | 投げて 500 になる。**画面には「保存できませんでした」が出る**（テスト済み）         |
| `parseDraft` の frontmatter が閉じていない場合   | 投げるところはテスト済み。一覧では中身なしとして扱う（テスト済み）                  |
| 本文の上限（1 MB）の境界                         | 上限があること自体は `title` の側でテスト済み。数は受け入れ条件が定めたものではない |
| `_redirects` が実際に効くか                      | Cloudflare が処理する。**デプロイしないと確かめられない**（M1 の一部）              |
| Vite のビルド成果物が Pages で正しく配信されるか | 同上                                                                                |

### 仕様として決めていない振る舞い

| 状況                                | 今の振る舞い                                                         | 決めていない理由                                 |
| ----------------------------------- | -------------------------------------------------------------------- | ------------------------------------------------ |
| 同じ下書きを 2 つの端末で同時に開く | 後から保存した側が 409 を受けて案内が出る                            | 1 人で使う前提だが、起こりうるので受け皿は作った |
| 下書きが非常に多い（100 件以上）    | 一覧が 1 件ずつ取りに行くので遅くなる                                | Unit 4 が一覧を育てるときに見直す                |
| 通信が切れている状態で書き続ける    | 保存が失敗し「保存できませんでした」が出る。**手元の入力は消えない** | 手元に貯めて後で送る仕組みは Unit 1 の範囲外     |

## この Unit の判定

**コードとビルドで確かめられる範囲はすべて満たしている。実際に動かす範囲は 1 件も確かめていない。**

Unit 1 を「完了」と呼べるのは、**上の M1〜M5 を人が実施したあと**。それまでは「実装は済み、動作は未検証」の状態。
