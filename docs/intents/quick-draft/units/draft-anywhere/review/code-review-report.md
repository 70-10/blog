# コードレビュー — draft-anywhere

対象は `c4bce1a..HEAD` の `packages/` と `vitest.config.ts` と `.prettierignore`（31 ファイル・2,130 行の追加）。

## コードレビュー結果

### 見つけた欠陥（2 件・どちらも直した）

#### 1. 一覧が 1 件の読み取り失敗で全滅する（`functions/api/drafts/index.ts`）

**壊れ方**: `Promise.all` の中で `parseDraft()` が投げると、一覧の API 全体が 500 になる。**手で編集した下書きが 1 件でもあると、一覧が開けず、他のどの下書きも開き直せなくなる。**

US-01 の「残した下書きを開き直せる」が、無関係な 1 件のせいで全件について成り立たなくなる。

**直し方**: 読めなかったものは中身なしとして並べ、開くことはできるようにした。黙って消さないのは、下書きが 1 件でも見えなくなると「残した」という前提が崩れるため。

**回帰テスト**: `should still list a draft whose frontmatter cannot be read`

#### 2. 最初の保存で打った分が消えうる（`src/routes/DraftEditorPage.tsx`）

**壊れ方**: 新規の下書きは最初の保存で URL が `/drafts/<id>` に変わる。変わると読み込みの処理が走って GitHub から取り直し、**保存を送っている間に打った分が取得の結果で上書きされて消える。**

「着想が失われないようにする」というこの Intent の目的に真っ向から反する。

**直し方**: 手元にある中身がどの下書きのものかを覚えておき、同じなら取りに行かない。

**回帰テスト**: `should not refetch after the first save changes the url`。**修正を戻すとこのテストが落ちることを確かめた**（戻すと 1 failed、戻すと 11 passed）。

### 直しの過程で入れた欠陥（1 件・直した）

2 の修正で、覚えておく値の初期値を `id` にしてしまい、**既存の下書きを開いたときに読み込みが始まらず画面が「読み込んでいます」から進まなくなった**。既存のテスト 6 件が落ちて分かった。初期値を「まだ何も読んでいない」に直した。
