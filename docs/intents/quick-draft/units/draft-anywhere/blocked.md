# 中断 — quick-draft / draft-anywhere（Stage 1: explore）

**要る判断: 管理画面をどこで動かし、「自分だけが入れる」をどう作り、リポジトリをどう書き込むか。**

この 3 つは別々には決められない。動かす場所を選ぶと使える認証が絞られ、認証の作り方でリポジトリを書く資格情報の持ち方が決まる。まとめて 1 つの案として選ぶ。

## なぜ無人のまま進めなかったか

[unattended.md](../../../../../.claude/skills/construction/references/unattended.md) の中断条件のうち 2 つに当たる。

1. **仕様・受け入れ条件に関わる。** 公開 URL と認証方式は外部に見える約束で、どこで動かすかを選ぶとその上に画面・裏側・テストの全部が乗る。あとから覆すのは実質的な作り直しになる
2. **Unit のスコープ外の用意が要る。** どの案を採っても、アカウントの作成・アプリの登録・秘密の値の登録はリポジトリの外の作業で、AI にはできない。構成だけ先に選んでも Stage 4（implement）が用意できない値の前で止まる

[03_units.md](../../03_units.md) と [execution-plan.md](../../execution-plan.md) も、この点で Unit 1 が止まる見込みが高いと書いている。

## 決めてほしいこと

3 案を並べる。**「人が用意するもの」が決め手になる**ので、そこを見て選んでほしい。

どの案も [ADR 0006](../../../../adr/0006-build-our-own-admin-screen-for-writing.md)（自作の管理画面）と [ADR 0003](../../../../adr/0003-articles-stay-as-markdown-in-this-repository.md)（記事の正はリポジトリ内の Markdown）の枠の中にある。

### 案 A: Cloudflare に置き、認証は Cloudflare Access に任せる

| 項目                 | 中身                                                                                                                                                                                                               |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 動かす場所           | Cloudflare（今このブログを配信しているところ）                                                                                                                                                                     |
| 自分だけが入れる作り | Cloudflare Access。許可したメールアドレスに使い捨てのコードを送って通す。**認証のコードを書かない**                                                                                                                |
| リポジトリの書き込み | サーバー側に置いた GitHub の資格情報で Contents API を叩く                                                                                                                                                         |
| **人が用意するもの** | ① Cloudflare の Zero Trust を有効にする ② Access のアプリケーションを登録し、許可するメールアドレスを指定する ③ GitHub App か細かい権限の個人アクセストークンを作る ④ ③ の値を Cloudflare の秘密の値として登録する |
| 利点                 | 認証を自分で書かない分、作る量が減り、抜けが入りにくい。配信の基盤が今と同じ                                                                                                                                       |
| 引き受けるもの       | 管理する画面が 1 つ増える（Cloudflare の Zero Trust）。無料で使える範囲の条件に依存する                                                                                                                            |

### 案 B: Cloudflare に置き、GitHub の OAuth で自分を認証する

| 項目                 | 中身                                                                                                                                                        |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 動かす場所           | Cloudflare（案 A と同じ）                                                                                                                                   |
| 自分だけが入れる作り | GitHub でログインし、そのアカウントが自分なら通す。認証とログイン状態の保持を自分で書く                                                                     |
| リポジトリの書き込み | ログインで得たトークンでそのまま Contents API を叩く（別の資格情報を持たなくてよい）                                                                        |
| **人が用意するもの** | ① GitHub で OAuth アプリを作る（識別子と秘密の値が出る）② ①の値を Cloudflare の秘密の値として登録する ③ ログイン状態の置き場（Cloudflare の保存領域）を作る |
| 利点                 | リポジトリを書く権限が「ログインした自分」と一致する。管理する画面が増えない                                                                                |
| 引き受けるもの       | 認証とログイン状態の保持を自分で書く。失効・再ログインの扱いも作る対象に入る                                                                                |

### 案 C: 画面は誰でも開ける場所に置き、鍵は端末に持たせる

| 項目                 | 中身                                                                                                                 |
| -------------------- | -------------------------------------------------------------------------------------------------------------------- |
| 動かす場所           | 今のブログと同じ（画面だけを配信する）                                                                               |
| 自分だけが入れる作り | **持たない。** 画面自体は誰でも開ける。書き込みは端末に保存した個人アクセストークンで行う                            |
| リポジトリの書き込み | ブラウザから直接 Contents API を叩く                                                                                 |
| **人が用意するもの** | ① 細かい権限の個人アクセストークンを作る ② 使う端末それぞれに貼り付ける                                              |
| 利点                 | 用意するものが最少。動かす場所を増やさない                                                                           |
| 引き受けるもの       | **Unit 1 の完了の目安「自分だけが入れて」を満たさない。** トークンが端末の保存領域に残り、端末を変えるたびに貼り直す |

**案 C は受け入れ条件との食い違いがある**ので、選ぶなら [03_units.md](../../03_units.md) の完了の目安を書き換える判断もあわせて要る。

### 案を比べる前に確かめたほうがよいこと

次はドキュメントとコードからは分からず、確かめていない。案 A・B のどちらでも関わる。

- 今の Cloudflare Pages のプロジェクトに、画面の裏側で動くコードを足せるか。別に Workers を立てることになるか
- Cloudflare Access を無料で使える範囲と、そこにメールアドレスを 1 つ登録するだけで足りるか
- 管理画面をどのドメインで開くか（ブログと同じドメインの下か、別に取るか）
