## 判定ルール

### 入れるか入れないか（認証）

| 判定           | 条件                                                                     | 結果                                  |
| -------------- | ------------------------------------------------------------------------ | ------------------------------------- |
| 画面を開けるか | Cloudflare Access のポリシーが通したか。**既定は拒否**                   | Access が判定する。アプリは関わらない |
| API を呼べるか | `Cf-Access-Jwt-Assertion` があり、署名・`iss`・`aud`・`exp` がすべて通る | 通らなければ 401                      |

- **ヘッダーの中身だけを見て通さない。** 署名を検証しないと別人になりすませる（[explore/constraints.md](../explore/constraints.md) の「管理画面の土台」）
- **JWKS の鍵が見つからないときは取り直してから 1 回だけ再検証する。** 鍵は 6 週ごとに入れ替わるので、キャッシュにない鍵 ID は「入れ替わった」のことがある。取り直しても見つからなければ 401
- **判定を画面側で行わない。** 画面は判定の結果（401 が返った）を受けて案内を出すだけ

### 下書きを作るか作らないか

| タイトル | 本文 | 結果         |
| -------- | ---- | ------------ |
| あり     | あり | 作る         |
| あり     | 空   | **作る**     |
| 空       | あり | **作る**     |
| 空       | 空   | **作らない** |

「空」は**前後の空白を落としたあとに長さ 0** であること。空白と改行だけの入力は空として扱う。

US-01 の 3 つの正常系（本文だけ / タイトルだけ / 両方あり）と異常系（両方空）がそのままこの表になる。

### 空になったとき（すでにある下書きを空にした場合）

**保存しない。** 最後に保存された中身がそのまま残る。

US-01 の受け入れ条件は「作られない」までしか定めていない。ここでの選択肢は 3 つあった。

| 案                             | 採否 | 理由                                                               |
| ------------------------------ | ---- | ------------------------------------------------------------------ |
| 保存しない（最後の中身が残る） | 採用 | 誤って全部消したときに取り返せる。捨てるのは Unit 4 の明示的な操作 |
| 空の状態を保存する             | 却下 | 「両方空の下書きは作らない」と食い違う状態がファイルに残る         |
| ファイルを消す                 | 却下 | 捨てるは Unit 4 の担当。自動保存が黙って消すのは戻せない           |

画面には「中身が空なので保存していません」を出す。**黙って保存しないのは避ける。**

### 一覧の並び順と見せ方

- 並び順は `updatedAt` の**新しい順**。`createdAt` ではない。US-04（Unit 4）の「見返して判断する」に効くのは最後に触った順
- タイトルが空の下書きは「（無題）」と出す。**Unit 1 はここまで。** 本文の冒頭を出して見分けられるようにするのは Unit 4（[03_units.md](../../../03_units.md)）
- **下書きが 1 件も無いのはエラーではない。** GitHub がディレクトリの無いことを 404 で返してくるが、これは空の一覧として扱う

### 保存の衝突

`PUT contents` は `sha` が合わなければ 409 を返す。

- 409 を受けたら**上書きしない**。画面に「他のところで変わっています。読み直してください」を出す
- 1 人で使う前提でも、同じ下書きを 2 つの端末で開けば起こる。**黙って上書きすると片方の書いたものが消える**

### コミットメッセージ

| 操作 | メッセージ                            |
| ---- | ------------------------------------- |
| 作成 | `[CI Skip] chore(draft): add <id>`    |
| 更新 | `[CI Skip] chore(draft): update <id>` |

- **`[CI Skip]` は先頭に置く。** Cloudflare Pages はこの印が先頭にあるときだけデプロイを飛ばす（大文字小文字は問わない）
- [docs/rules/project.md](../../../../../rules/project.md) は Conventional Commits を定めているが、印を先頭に置く必要があるため型がその後ろに来る。**この形は人が打つコミットには使わない。** 管理画面が自動で打つものに限る

## バリデーション

### 裏側（API）

すべての経路で、認証（上の「API を呼べるか」）を通したあとに検査する。**画面を信じない。**

| 対象               | 検査                                           | 通らないとき |
| ------------------ | ---------------------------------------------- | ------------ |
| `id`（経路の一部） | `crypto.randomUUID()` が作る形に一致する       | 400          |
| `title`            | 文字列である。1,000 文字以内                   | 400          |
| `body`             | 文字列である。1 MB 以内                        | 400          |
| `title` と `body`  | 両方が空（前後の空白を落として長さ 0）ではない | 422          |
| `sha`（更新のみ）  | 文字列がある                                   | 400          |

- **`id` の形を検査するのは、経路をファイルのパスに使うため。** `../` を含む値でリポジトリの別の場所を書き換えられないようにする。`randomUUID()` の形に一致することを確かめれば、記号は `-` と 16 進数だけになる
- 上限（1,000 文字・1 MB）は誤操作と暴走を止めるためのもの。**受け入れ条件が定めた数ではない**ので、実装のときに窮屈なら見直してよい

### 画面

- **保存を止める検査は置かない。** 判定は裏側が持つ。画面の検査は案内を早く出すためだけ
- 両方が空のときは保存の要求を送らず、「残すものがありません」を出す
- 裏側が 422 を返したときも同じ案内を出す。**画面の検査を通り抜けた場合の受け皿を残す**

### 変えない検査

| 検査                                      | 扱い                                                                                                                                                                |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 記事のスキーマ（`src/content.config.ts`） | **触らない。** 下書きは posts コレクションの外（[ADR 0009](../../../../../adr/0009-drafts-live-outside-the-posts-collection-and-commit-with-a-build-skip-flag.md)） |
| 校正（textlint）                          | **下書きには掛けない**（[00_intent.md](../../../00_intent.md) の Out）。対象は `src/content/posts/**/*.md` のままにする                                             |
| `pnpm create-post` のタグ必須             | **変えない**（US-03 の「今と同じように動く」）                                                                                                                      |

### 検査の経路を壊さないための決まり

- **`.prettierignore` に `src/content/drafts/` を足す。** `prettier . --check` が下書きを検査対象にすると、スマホで書いた整形されていない文章で CI が落ちる（[logic-model.md](logic-model.md) の「検査の経路への影響」）
- **依存を足したら `pnpm-lock.yaml` を同じコミットに入れる。** CI が `git diff --exit-code pnpm-lock.yaml` で見ている
