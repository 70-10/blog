# 記事の正はこのリポジトリ内の Markdown のままにする

Status: accepted
発生元: quick-draft

記事を書き始める間口を広げる検討で、記事データをどこに持つかを問い直した。結論として、記事の正は
`src/content/posts/*.md` のまま据え置く。スマホなどからの入口を増やすときも、その入口は最終的に
このリポジトリの Markdown を作る手段として位置づける。理由は、記事が手元のテキストファイルであることで
得られる移植性と所有権を手放したくないため。

却下した代替案: 外部の記事管理サービス（Contentful など）を正にする — 編集画面が最初から用意され、
どの端末からでも書ける利点はあるが、過去に Contentful を使っていて管理のしづらさで手放した経緯がある。
同じ形に戻すことになるため。
