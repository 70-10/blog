# 実行中の記録はステージごとに 1 ファイルに分け、ステージタグを廃止する

Status: accepted
発生元: ai-dlc-skills（Unit 分割の追加）

移植当初は `memory.md` を作業ごとに 1 ファイルにまとめ、エントリに `[step0]` `[implement]` のようなステージタグを付けて絞り込んでいた。Unit 分割を入れると Unit という軸が増え、この形が持たなくなる。Unit B の implement ゲートに Unit A の `[implement]` エントリが混ざるうえ、タグにも見出しにも Unit を表す場所が無い。元ネタの `awslabs/aidlc-workflows` を確認したところ、実行中の日記は `<record>/<phase>/<stage>/memory.md` とステージごとに 1 ファイルで、ステージタグを持たない形だった（ガイド・`conductor.md`・`tests/unit/t199-learnings-memory-path.test.ts` の 3 つが一致）。ファイルのパスがステージを表すので、軸が足りなくなる問題そのものが起きない。この形に合わせ、あわせて昇格先も `docs/rules/{project,inception,construction}.md` とフェーズで分ける。失うのはステージをまたぐ引き継ぎで、これは「未解決の疑問と矛盾はそのステージ内で解決してから完了する」という進め方で置き換える。

却下した代替案: タグに Unit を足す（`[implement:unit1]` のような形） — スクリプトの正規表現を直せば動くが、軸が増えるたびにタグの構文を広げることになる。形式が手順の要求に追いつかない同じ問題を繰り返すため。

却下した代替案: 1 ファイルのままにして Unit ごとにディレクトリを分けない — 変更は小さいが、Unit ごとの進捗を別々に持てず、Unit に分ける意味が実装の順序を決めるだけに薄まるため。
